# KindlePDF 0.6.3 — diagnóstico do cache e ensaio de PDF

Data: 29/09/2026. Ambiente de build e ensaio: Windows 11 x64, Python 3.12 no ambiente de build. Release pessoal em rascunho; não há validação em Windows limpo nem revisão concluída das licenças de distribuição.

## Motivo da alteração

Em outro computador, o usuário confirmou que o livro selecionado abre integralmente no Kindle para Windows 1.0.25218. A tentativa do KindlePDF 0.6.2 terminou com `protected_or_unreadable` e `Adaptador: unsupported`. Uma verificação de existência, sem ler o cache, retornou `True` para `LocalCache/Local/Microsoft/Crypto/PCPKSP` na instalação do Kindle. O código do arquivador v10.0.32 copia o conteúdo dessa pasta para `LocalAppData/Microsoft/Crypto/PCPKSP`, fora da área temporária do KindlePDF. O adaptador já bloqueava essa operação; a interface não distinguia o motivo e sugeria indevidamente que o livro poderia estar incompleto.

Na versão 0.6.3, o adaptador retorna o código constante `external_key_cache` antes de executar o arquivador. O pipeline registra apenas esse código no diagnóstico do manifesto, sem chave, conteúdo ou caminho do cache. A interface explica que a conversão foi interrompida para evitar a cópia persistente. O cache do Kindle não foi alterado. **Esta versão não converte o livro nesse outro computador**; a mudança é de diagnóstico e segurança, não de compatibilidade.
